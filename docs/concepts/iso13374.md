# The six blocks

`otwin` is laid out as the six data-processing blocks of **ISO 13374**, the
standard for condition monitoring and diagnostics of machines. The layout is
load-bearing rather than decorative: each block has one job, and a number can be
traced back through them to the register it was read from.

```{mermaid}
flowchart LR
    DA[Data Acquisition<br/><code>otwin.io</code>] --> DM[Data Manipulation<br/><code>otwin.signal</code>]
    DM --> SD[State Detection<br/><code>otwin.estimate</code>]
    SD --> HA[Health Assessment<br/><code>otwin.model</code>]
    HA --> PA[Prognostic Assessment<br/><code>otwin.forecast</code>]
    PA --> AG[Advisory Generation<br/><code>otwin.advise</code>]
```

**Data Acquisition** ({mod}`otwin.io`) reads a device or a registered dataset.
Every value carries a {class}`~otwin.io.Quality` flag, because a sensor that
returns a plausible number after a failed read is more dangerous than one that
returns nothing.

**Data Manipulation** ({mod}`otwin.signal`) puts irregular samples on a uniform
grid. {func}`~otwin.signal.resample` will not invent data: it stops at the last
whole step rather than extending half a step past the final measurement, and
{func}`~otwin.signal.coverage` reports what fraction of the grid is a real
measurement rather than a filled gap.

**State Detection** ({mod}`otwin.estimate`) recovers what you cannot measure.
{class}`~otwin.estimate.EnergyConsistentObserver` is the one worth knowing
about: a measurement correction that would manufacture stored energy is
rejected, so the filter cannot quietly break the property the model was chosen
for.

**Health Assessment** ({mod}`otwin.model`) is the asset written as an energy
balance. See [Port-Hamiltonian systems](port-hamiltonian.md).

**Prognostic Assessment** ({mod}`otwin.forecast`) is what happens next and how
sure. See [Leakage-free evaluation](leakage.md) and
[Calibrated intervals](conformal.md).

**Advisory Generation** ({mod}`otwin.advise`) turns a forecast into a decision,
or declines. See [Validity envelopes](envelopes.md).

## Why this matters for provenance

{class}`~otwin.interfaces.TwinManifest` records the path a twin took through
these blocks: what it is, what data it was fitted on, under which protocol it
was validated, and how its intervals were calibrated. The manifest is what
{class}`~otwin.advise.Envelope` reads. A twin with no manifest is not a twin
with a permissive envelope — it is one that cannot answer.
